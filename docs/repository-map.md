# 应用与 reverse 仓库的联动

| 仓库 | 面向谁 | 维护内容 |
| --- | --- | --- |
| [witrn-k2-mac](https://github.com/lliooly/witrn-k2-mac) · 维简 Mac | 使用者与应用开发者 | SwiftUI 应用、集成后台、安装使用、应用测试与发布 |
| [WITRN-K2-REVERSE](https://github.com/lliooly/WITRN-K2-REVERSE) | 协议研究者与二次开发者 | HID / DFU、文件格式、恢复方法、接口契约、参考实现与证据 |

本仓库的 `k2up/` 是应用实际使用的后台。reverse 仓库里的参考实现独立维护；不存在包版本依赖、Git submodule 或自动复制。目录同名不代表实现已同步。

## 改动流程

1. 涉及命令号、字段、地址、文件格式或校验时，先记录证据与未知部分，明确是静态分析、模拟还是实机结果。
2. 在应用侧补充合成样本、失败路径和版本边界。不要为更新文档而执行真实擦写。
3. 在对应 PR 中链接另一仓库的具体提交或文件，不只链接首页；注明哪些结论已经同步，哪些尚未同步。
4. 更新相关接口说明和验证记录后，再更新用户文档与更新日志。

研究结论修正优先记录到 reverse；应用交互、打包和运行问题优先在应用仓库报告。共享协议缺陷应在两边建立关联记录，避免各自修复后产生行为差异。

本地用于研究的 `WITRN-K2-REVERSE/` 独立检出目录被应用仓库忽略；不要把整个研究仓库作为未声明的嵌套副本提交。
