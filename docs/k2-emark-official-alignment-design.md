# E-Mark 官方工具功能对齐方案

2026-10-11。目标是对齐用户提供的 WITRN E-Marker 工具截图中的操作能力和数据流，沿用现有 macOS 应用样式。

参考：https://github.com/JohnScotttt/WITRN-K2-Quick-Reference-Manual/raw/main/pictures/io_E-Marker.png

## 推荐范围

页面由参数编辑器、设备读出列表和本地待写列表组成。两个列表独立保存；读取设备只更新读出列表，不覆盖待写配置或未保存工程。选中读出记录可查看参数、保存为官方 `.wtemark` 文件，或通过明确的添加操作加入待写列表。参数编辑器的改动只有在添加／更新待写配置后进入待写集合。

参数编辑器提供名称、PD 版本、ID Header、XID、Product 和 Cable 各字段，以及对应的原始 VDO 编辑和预览。添加「重置参数」，其初始值先与已有官方重置方法证据核对，不把应用模板称为设备内置档位。保留扩展 VDO 和附加字段编辑能力。

待写列表支持添加、更新选中配置、删除、清空、排序和设置默认组，容量最多 10 组。删除和清空仅修改本地数据，支持撤销；设备写入仍通过「备份并写入」明确触发。清空后写入的确认说明将清空设备自定义配置。

提供明确的「导入参数」和「保存参数」入口，兼容官方 66 字节 `.wtemark`。整组 `.k2emark` 工程继续保存待写集合及默认组，不把上次读取的设备快照误当作待写集合。

读取空白配置区显示「设备尚未保存自定义 E-Mark 配置。内置档位不在本次读取范围内」，保留原始备份；读取失败或格式异常不替换待写列表。已读取数据应显示其来源设备，设备变化或写入完成后标明其为上次读取快照，避免冒充设备当前状态。

## 方案取舍

1. 推荐完整对齐截图能力和两份列表的数据流。可以避免设备读取覆盖本地草稿，也使操作名称与官方工具对应。
2. 只补重置／清空按钮，保持一个列表。改动更小，但无法对齐读出与待写分离，不满足本次完整对齐目标。
3. 逐像素复制 Windows 界面。需要额外布局工作，对功能对齐没有必要；本方案沿用 macOS 组件。

## 实现和验证

沿用现有 K2Core 数据模型、EmarkStore、EmarkView 和固定地址资源后台。扩展 Store 管理设备快照、编辑草稿和待写集合；读取回调不再直接替换本地 bank。现有完整双遍备份、固定扇区写入、读回比较、未保存保护和格式校验继续使用。

测试覆盖设备读取不覆盖本地草稿、读出配置加入待写集合、参数导入导出往返、重置值、10 组容量、更新与未知位保留、清空撤销、默认组及读取来源状态。运行 Python 资源回归和 Swift 模型／Store 测试，构建应用验证布局。

对齐范围不包含读取固件内置档位、远程开关虚拟 E-Mark、主动采集物理线材身份或私有加密认证；截图没有这些独立入口，现有协议也未确认这些读取或控制方式。E-Mark 实机擦写与设备使用效果单独记录验证状态，不用模拟测试代替。

在当前目录和分支工作，不创建 worktree，不使用视觉伴侣。
